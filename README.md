| Режим   | Запуск 1 | Запуск 2 | Запуск 3 | Запуск 4 | Запуск 5 | Минимум | 
| ------- | -------: | -------: | -------: | -------: | -------: | ------: |

| Release |      620 |      615 |      618 |      622 |      619 |     615 |      
В моём эксперименте Release оказался быстрее Debug
Когда я открыл в ILSpy сначала Debug-сборку, а потом Release, разница была видна сразу:
В Debug есть куча инструкций nop — это пустые операции, которые ничего не делают. В Release их нет вообще.
В Release пропали лишние операции с локальными переменными: в Debug результат сначала сохраняется в переменную (stloc), а потом читается обратно (ldloc). В Release этого нет, значение сразу идёт на возврат.
Release-код выглядит чище и короче.
##Ответы на контрольные вопросы
1. IL-код — промежуточный код, который появляется после компиляции C#
программы. Он хранится внутри сборки вместе с метаданными: информацией о 
типах, классах, методах и других элементах программы. IL не привязан 
непосредственно к конкретному процессору и используется .NET на разных 
платформах.
2. Потому что внутри .dll лежит не только IL-код, но и метаданные — информация о классах, методах, типах. По этим данным ILSpy спокойно восстанавливает код, который выглядит почти как исходник. Поэтому компиляция — это не защита от просмотра.
3. В Debug куча лишнего: nop, лишние локальные переменные, сохранение и чтение из них (stloc/ldloc), переходы br.s. В Release всё это выкинуто, остались только нужные команды: загрузить аргументы, сложить, вернуть результат.
4. Потому что при сборке Release компилятор включает оптимизации: убирает пустые операции, избавляется от ненужных переменных, встраивает короткие методы прямо в место вызова. JIT при запуске тоже оптимизирует Release-код агрессивнее. В итоге программа делает меньше работы и выполняется быстрее.
5. Потому что строки хранятся в .dll в открытом виде (UTF-16), и их можно найти обычным HEX-редактором или декомпилятором. Я сам в этом убедился, когда открыл Lab02.dll в Hex Editor и увидел свои строки Debug vs Release и SumTo. Никакого шифрования там нет, так что пароли и ключи в коде хранить нельзя.
